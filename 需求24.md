我想重新设计当前项目里的 participant calibration reuse / quick check 流程。

你已经检查过现有代码，并确认目前的主要问题是：

* Full finger calibration 当前只有一次 Open / C / Pinch static hold；
* Quick check 当前实际上只检查 Open + wrist neutral；
* finger quick check 主要依赖 current Open 与 saved Open 的绝对距离；
* wrist quick check 仍然调用 midpoint-centered neutral classifier；
* quick check fail 后很容易直接触发 full recalibration；
* 当前 calibration 缺少 repetition-to-repetition consistency；
* 这导致 calibration reuse 在 pilot 中几乎失去意义。

现在请基于以下新版设计继续讨论数据结构和最小实现方案。

暂时不要直接大规模修改代码。

---

# 1. 核心设计原则

Full calibration 的职责是：

> 建立 participant-specific、但具有行为稳定性的 action space。

Quick check 的职责是：

> 判断以前保存的 action space 今天是否仍然可以可靠使用。

Quick check 不应该：

> 每个 session 重新估计一个新的 action space。

也不应该：

> 因为 participant 今天某个数值没有精确复制上一次 reference，就立即重新标定。

另一方面，也不能为了提高 reuse rate 而简单放宽所有 tolerance。

核心判断应该同时包含：

1. participant 今天有没有正确、稳定地做出要求的状态；
2. saved calibration 今天是否仍然能够正确分类这些状态。

---

# 2. 不采用“无人确认的连续动作自动分段”

之前考虑过让 participant 连续执行：

Open → C → Pinch → C → Open

然后程序自动从连续轨迹中识别和切分各个状态。

现在我不希望采用这种方式作为第一版。

原因是：

* participant 可能把它理解成连续动作；
* 不同 participant 的动作速度不同；
* 某些人不会在状态之间明显停顿；
* transition samples 很容易污染 calibration distribution；
* 程序很难仅凭 distance 确定 participant 是否已经真正进入实验要求的姿态。

因此：

> 不要让程序自动猜 participant 什么时候已经完成了 Open / C / Pinch 姿态。

第一版应该使用 **guided staged acquisition**。

---

# 3. Full calibration 的每一个状态都使用明确阶段

例如一个 Open phase：

1. 屏幕显示：
   `OPEN`

2. Participant 按照实验员已经示范过的标准动作摆出 Open。

3. Participant 或 experimenter 明确确认：
   “已经摆好，可以开始采集”。

可以通过现有键盘输入实现，例如 Space / Enter。

不要让“屏幕一出现 OPEN”就立即开始正式采样。

4. 收到人工确认以后，程序进入：

   `WAIT_FOR_STABILITY`

5. 程序只负责判断当前信号是否足够稳定。

例如可以使用：

* sliding-window MAD
* sliding-window range
* valid sample ratio

具体指标请根据现有代码提出简单方案。

6. 信号连续稳定达到 configurable dwell time 后，例如候选：
   300–500 ms

才进入：

`RECORD_STABLE_WINDOW`

7. 正式采集一个固定长度的 stable window，例如候选：
   1–2 s

8. 如果 recording window 内明显失去稳定：

   * 当前 attempt 作废；
   * 不接受这段数据；
   * 回到 `WAIT_FOR_STABILITY`；
   * 不要求 participant 重新切换到别的状态。

9. 成功后程序提示该 phase 完成，并进入下一个状态。

因此一个 phase 的逻辑应类似：

SHOW TARGET POSTURE
↓
WAIT FOR HUMAN CONFIRMATION
↓
WAIT FOR SIGNAL STABILITY
↓
RECORD STABLE WINDOW
↓
QUALITY OK?
yes → ACCEPT
no  → REACQUIRE SAME STATE

---

# 4. 人工确认和自动稳定检测的职责要严格分开

这里我非常在意一个边界：

> Human confirmation 表示 participant / experimenter 认为要求的姿态已经摆出来了。

而：

> Stability detector 只判断这个姿态的数据是否足够稳定，适合采集。

自动算法不要替代人工语义确认。

例如一个 participant 做了一个非常接近 Pinch 的“C”，而且保持得非常稳定。

程序可以判断：

> stable = true

但这不意味着：

> behaviorally valid C = true

最终姿态是否满足 calibration geometry，应在后面的 QC 中判断。

所以：

> stability ≠ behavioral validity

请在代码结构里保留这个边界。

---

# 5. Full finger calibration 使用 multiple repetitions

第一次完整 finger calibration 不再只有：

Open × 1
C × 1
Pinch × 1

而希望估计 participant 正常动作的 repeatability。

目前建议先讨论：

> 3 repetitions 是否合理。

可以按照明确的 staged sequence，例如：

Cycle 1:
Open → C → Pinch

Cycle 2:
Open → C → Pinch

Cycle 3:
Open → C → Pinch

也可以保留：

Open → C → Pinch → C → Open

作为 participant 的动作顺序提示，但每个状态仍然必须独立：

* 显示提示；
* 人工确认；
* 稳定检测；
* stable-window recording。

不要自动从连续运动中 segmentation。

我目前更倾向于代码层面把每次 acquisition 明确保存为：

* open_rep1
* contact_rep1
* pinch_rep1
* open_rep2
* contact_rep2
* pinch_rep2
* open_rep3
* contact_rep3
* pinch_rep3

这样数据结构简单且容易调试。

---

# 6. Full calibration 需要同时检查两种稳定性

当前代码主要能看到：

> within-hold stability

例如某次 C 保持 2 秒，MAD 很小。

但 pilot 已经暴露：

participant 可能每一次 C 都保持得非常稳定，但三次 C 的位置差异很大。

因此必须区分：

## A. Within-hold stability

每一次 repetition 内：

* median
* MAD
* p10
* p90
* valid_count
* duration_s

## B. Between-repetition reproducibility

例如三个 C repetition：

0.080
0.043
0.076

即使每一次 MAD 都很小，整体 calibration 仍然不应该被认为具有良好的 behavioral consistency。

---

# 7. Finger calibration 保存 repetition-level 数据

希望新的 calibration result 至少能够保存：

每个 repetition/state：

* median
* MAD
* p10
* p90
* valid_count
* acquisition_duration_s

总体 summary：

* open_median

* contact_median

* pinch_median

* open_MAD / pooled variability

* contact_MAD / pooled variability

* pinch_MAD / pooled variability

* open_contact_gap

* contact_pinch_gap

* normalized_contact_position

以及 repetition-level normalized positions。

---

# 8. C-shape 使用 normalized Open–Pinch action space

建议使用：

normalized_contact_position =
(open_median - contact_median)
/
(open_median - pinch_median)

其中：

Open = 0
Pinch = 1

这样可以描述 C 在 participant 自己的 Open–Pinch range 中处于什么位置。

例如三个 C repetition：

0.52
0.57
0.54

说明比较一致。

而：

0.55
0.84
0.61

说明 participant 的 C definition 不稳定。

第一版可以考虑使用：

contact_rep_position_range =
max(rep_positions) - min(rep_positions)

作为容易理解的 repetition consistency QC。

但请同时保存 MAD / SD 或其他统计量，未来根据更多 pilot 决定正式指标。

不要现在替我硬编码：

“C 必须在 0.3–0.7”

这类固定阈值。

相关 threshold 先 config 化，并根据后续 pilot 冻结。

---

# 9. Full calibration QC

希望至少包含以下层次。

## Signal quality

* tracking valid
* sufficient valid samples
* signal continuity reasonable
* within-hold variability acceptable

## State ordering

* Open > C > Pinch

## State separation

* Open–C gap sufficiently large
* C–Pinch gap sufficiently large

最好能考虑相对于 participant Open–Pinch range 的 normalized separation，而不是只使用绝对毫米。

## C relative position

* C 不能过分靠近 Open
* C 不能过分靠近 Pinch

具体阈值先 config 化。

## Repetition consistency

* Open repetitions reasonably reproducible
* C repetitions reasonably reproducible
* Pinch repetitions reasonably reproducible

尤其 C 应重点检查 normalized position 的 repetition spread。

# 10. Quick check 仍然使用 staged acquisition

Quick check 也不要让 participant 自己快速连续做：

Open → C → Pinch → C → Open

然后程序自动 segmentation。

Quick check 应复用 Full calibration 的相同 interaction paradigm，只是更短。

例如：

OPEN
→ participant摆好
→ human confirmation
→ wait stable
→ record shorter window

C
→ 同样流程

PINCH
→ 同样流程

WRIST NEUTRAL
→ 同样流程

因此 Quick check 的体验可以很快，但仍然明确。

可以考虑：

* shorter stable dwell
* shorter recording window

例如候选：

* stability dwell 300–500 ms
* recording 0.5–1 s

具体值根据现有采样率和 pilot 再决定。

目标是：

> 整套 quick check 在十几秒到几十秒内完成，

而不是重新变成几分钟 full calibration。

---

# 11. Quick check 不需要重新做 Left / Right / Up / Down

Full wrist calibration 才采：

* Neutral
* Left
* Right
* Up
* Down

后续 quick check 只采：

> Wrist Neutral

同样采用：

screen prompt
→ participant摆好
→ human confirmation
→ signal stability
→ short recording

---

# 12. Wrist quick check 必须改成 neutral-centered

当前 quick check 仍然调用旧：

classify_wrist_rotation()

而该分类器的 neutral 仍可能来自：

midpoint(left_mean, right_mean)

或：

midpoint(up_mean, down_mean)

这已经被 pilot 数据证明可能产生 false negative，因为 asymmetric movement amplitude 会让真正 neutral=0 落在旧 neutral region 之外。

因此 quick check 不应该使用旧 midpoint-centered neutral label。

希望改成：

1. 使用 Full calibration 保存的 participant neutral reference；
2. 使用保存的 LR / UD axis；
3. 把当前 neutral samples 投影到这些 axis；
4. 判断当前 neutral 是否仍处于 neutral-centered acceptable region；
5. tolerance 主要来自：

   * neutral noise
   * neutral repetition variability
   * action separation

请先根据当前 `wrist_rotation.py` 的实际字段设计，不要假设已有 implementation 已经正确。

# 13. Quick check 必须同时检查两个层面

这是新版设计里非常重要的一点。

## A. Current-state validity

首先判断 participant 今天执行的状态本身是否合理：

* stable signal
* Open > C > Pinch
* state separation sufficient
* C normalized position reasonable
* repetition consistency acceptable

这一层回答：

> participant 今天有没有把动作做正确？

## B. Saved-calibration compatibility

即使今天 Open/C/Pinch 彼此分得很好，也不意味着保存的旧 calibration 仍然可以继续使用。

因此还需要：

> 直接使用 saved calibration boundaries/model 去分类今天 quick-check samples。

至少检查：

* current Open 是否仍被 saved calibration 判为 Open
* current C 是否仍被 saved calibration 判为 C
* current Pinch 是否仍被 saved calibration 判为 Pinch
* current Wrist Neutral 是否仍落在 saved neutral-centered region

最好记录：

* expected-state classification proportion
* distance/margin to saved decision boundaries

例如：

Saved calibration:
Open = 0.140
C = 0.070
Pinch = 0.020

Saved C/Pinch boundary = 0.045

Today:
Open = 0.110
C = 0.040
Pinch = 0.000

今天三个状态本身仍然满足：

Open > C > Pinch

但旧 calibration 会把当前 C 判成 Pinch。

这种情况必须：

FAIL saved-calibration compatibility

不能因为 current relative geometry 很漂亮就 PASS。

因此最终 Quick check 回答的是：

> Is the participant currently producing valid states AND can the previously saved calibration still classify them correctly?

# 14. Quick check 第一次失败后不要立即 recalibrate

第一次 FAIL 后：

不要立即 full recalibration。

根据 component-level failure reason 给 participant 提示，例如：

* Please fully open your hand.
* Please form the standard C-shape without pinching.
* Please pinch fully.
* Please relax your wrist to neutral.

然后重新做：

Quick check attempt 2

如果 attempt 2 PASS：

> REUSE existing calibration

如果 attempt 2 仍然 FAIL：

> 才进入 recalibration decision。

第一版可以保持：

fail twice → full recalibration

暂时不要做 targeted partial recalibration。

---

# 15. Human confirmation 也适用于 guided retry

如果某一个状态失败，不要自动让程序不断猜 participant 什么时候重做完。

仍然：

显示失败状态提示
→ participant重新摆姿态
→ participant / experimenter确认已经摆好
→ 稳定检测
→ reacquire

我希望实验员仍然能够观察 participant 的实际姿态。

Calibration 是实验标准化流程，不希望为了自动化而完全移除人工监督。

---

# 16. Quick check tolerance 应来自 participant-specific variability

不要只是：

5 mm → 10 mm → 20 mm

这样不断放宽 absolute threshold。

Full calibration 通过 repeated acquisition 后，应该得到 participant 自己的：

* state variability
* repetition variability
* Open–Pinch range
* state separation margins
* neutral variability

Quick check tolerance 应尽量基于这些 participant-specific distributions。

但第一版不要引入复杂 machine learning。

希望是：

* 简单
* 可解释
* configurable
* 能打印 failure reason
* 能用 pilot 数据调整

---

# 17. Legacy calibration

旧 calibration bundle 需要继续保持可读取，以便：

* old pilot analysis
* backward compatibility

但如果旧 bundle 缺少：

* repetition-level statistics
* normalized C variability
* new QC fields
* new neutral-centered reuse fields

我倾向：

> old bundle 不再参加新的 formal reuse protocol。

第一次使用新版 runner 时：

legacy calibration detected
→ perform one new full calibration
→ save calibration_v2
→ future sessions use new quick check/reuse

不要为了兼容旧 bundle 而在正式新实验里继续 fallback 到旧 quick check。

# 最终设计原则

请一直围绕下面三个原则：

> Full calibration establishes the participant's repeatable action space.

> Human confirmation identifies when the participant believes the requested posture has been reached; automatic stability detection determines whether the signal is suitable for recording.

> Quick check validates whether the previously established calibration remains behaviorally valid and computationally usable; it should not silently redefine the participant's action space every session.

先给设计和数据结构，不要直接开始实现。
